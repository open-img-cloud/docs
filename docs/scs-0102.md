# SCS-0102 image metadata

The [Sovereign Cloud Stack](https://scs.community) standard
[SCS-0102](https://docs.scs.community/standards/scs-0102-v2-image-metadata) defines the Glance
properties a public image should carry, so that users and tools know where it comes from, how
often it is replaced and how long it is supported. The catalog publishes them in the
`glance_properties` of every artifact in [`index.json`](catalog-index.md); oic-sync, the
[Terraform provider](terraform.md), the [Ansible collection](ansible.md) and the commands of the
image pages set them on import.

## Properties

| Property | Value in the catalog |
|---|---|
| `architecture`, `hw_disk_bus`, `hw_scsi_model`, `hw_vif_multiqueue_enabled`, `hw_qemu_guest_agent`, `os_require_quiesce` | Technical properties, see [catalog index](catalog-index.md#indexjson-oic-indexv1) |
| `os_distro`, `os_version` | OpenStack names of the distribution and its version. Product images carry their own release: OPNsense (`26.7.9`, on `os_distro=freebsd`), Flatcar, Talos Linux, CirrOS. The OpenStack service images carry the OpenStack series of each artifact (`2026.2`), not the Ubuntu release underneath. Absent for some images, see below |
| `image_original_user` | The default user (`login_user`), or `none` for images without one |
| `image_source` | The versioned URL of the qcow2 |
| `image_build_date` | Build time of the artifact, ISO 8601 UTC |
| `image_description` | The image page, `https://openimages.cloud/images/<id>/` |
| `os_purpose` | `generic` for the general-purpose images; `custom` for service images, `cloud-rescue` and the non-default variants (Alpine Linux UEFI, Alpaquita musl), since SCS-0102 allows one generic image per distribution, version and architecture; `network` for OPNsense, `k8snode` for Talos Linux, `minimal` for CirrOS |
| `replace_frequency` | `critical_bug`: a new version is published when upstream fixes a critical bug or a security issue (and at each upstream point release). `never` for CirrOS |
| `provided_until` | End of upstream security support (from [endoflife.date](https://endoflife.date)), or `none` when unknown |
| `uuid_validity` | `last-3`: an image imported by oic-sync keeps its UUID while it is one of the three newest versions (with `--keep 3` or more) |

Glance `min_ram` (an image attribute, not a property) is published as `min_ram` in the index:
1024 MiB by default, less for small images (CirrOS, Alpine Linux), more for Talos Linux.

## Checking an image

The SCS project publishes the conformance test,
[`image_metadata.py`](https://github.com/SovereignCloudStack/standards/tree/main/Tests/iaas/scs_0102_image_metadata).
Run it against a project where the images were imported with oic-sync.

## Known gaps

- Rolling distributions have no release to put in `os_version`: Gentoo and Alpaquita publish
  none, Arch Linux publishes its upstream build id. How SCS-0102 should represent them is under
  discussion; the catalog will follow. The snapshot is always in `image_build_date` and
  `oic_version`.
- OPNsense and the OpenStack service images put a product version or an OpenStack series in
  `os_version`, while `os_distro` names the system underneath (FreeBSD, Ubuntu).
- `min_ram` is the value the image needs in practice; the boot test does not run at exactly that
  amount of memory.
- `replace_frequency` describes the release policy, not a fixed schedule: an image whose
  upstream publishes nothing new keeps its last version, so its `image_build_date` can be older
  than a month.
