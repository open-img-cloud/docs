# Catalog index and machine-readable files

Everything the website shows is also available as JSON or YAML, so imports and updates can be
automated. All files are served by `https://images.openimages.cloud`.

| File | Content | Updated |
|---|---|---|
| [`/index.json`](https://images.openimages.cloud/index.json) | Latest version of every recommended image, schema `oic-index/v1` | At each website build (daily, and after each release) |
| [`/osism/images.yml`](https://images.openimages.cloud/osism/images.yml) | The same images for osism openstack-image-manager | Same as `index.json` |
| `/<id>/versions.json` | Every published version of one image, schema `oic-versions/v1` | At each release of that image |
| `/<id>/<version>/MANIFEST.json` (or `MANIFEST-<variant>.json`) | Build provenance and digests of one artifact | Written once per release |
| [`/_stats.json`](https://images.openimages.cloud/_stats.json) | Download counts per image, version and file | Computed by the Worker, cached at least one hour |

`index.json` and `osism/images.yml` are generated by the website build
(`oic-website/src/lib/catalog-index.ts`) and relayed on the registry host by the
`images-router` Worker; they are also reachable at `https://openimages.cloud/index.json` and
`https://openimages.cloud/osism/images.yml`. Files at a bucket root (`versions.json`) and under
`latest/` are cached for 5 minutes; files under a versioned path, including manifests, are
immutable.

## `index.json` (`oic-index/v1`)

The schema only gains fields over time; a breaking change would bump it to `oic-index/v2`.
Images with status `preview` are left out, and an image appears only once at least one artifact
manifest could be read.

```text
schema                     "oic-index/v1"
generated_at               ISO 8601 UTC
base_url                   "https://images.openimages.cloud"
signing
  type                     "cosign-keyless"
  bundle_format            "sigstore-bundle"
  certificate_identity_regexp
  certificate_oidc_issuer
images[]
  id                       catalog id, also the registry path segment (e.g. "debian-13")
  title                    display name (e.g. "Debian 13")
  status                   "stable" or "archive"
  status_note              one-line note (EOL date, known issue) or null
  repo                     GitHub repository URL
  login_user               default user, or null (service images without one)
  os_distro, os_version    OpenStack properties, or null
  latest_version
  versions_url             URL of versions.json, or null when the image has none yet
  tags[]
  glance_properties        image-level properties (no per-artifact keys)
  optional_glance_properties   supported but opt-in, today {"hw_rng_model": "virtio"}
  artifacts[]              one per variant of the latest version
    variant                variant id (e.g. "uefi") or null
    version, arch, format, firmware ("bios" or "uefi")
    url                    versioned URL of the qcow2
    sha256, sha512         sha512 may be null for older manifests
    size, virtual_size     bytes, may be null for older manifests
    bundle_url, manifest_url
    built_at, build_url, commit, signed
    glance_properties      complete property set to pass to `openstack image create`
```

Per-artifact `glance_properties` combine: `os_distro`, `os_version`, `os_admin_user`,
`architecture`, the defaults (`os_type=linux`, `hw_qemu_guest_agent=yes`, `hw_disk_bus=scsi`,
`hw_scsi_model=virtio-scsi`, `hw_vif_multiqueue_enabled=true`, `os_require_quiesce=yes`),
`hw_firmware_type=uefi` and `hw_machine_type=q35` for UEFI artifacts, any per-image overrides, and
the identification keys `oic_id`, `oic_version` and `oic_sha256`.

Example queries:

```sh
# Versioned URL and sha256 of every artifact
curl -fsS https://images.openimages.cloud/index.json \
  | jq -r '.images[].artifacts[] | "\(.url)  \(.sha256)"'

# Glance properties of one image as --property flags
curl -fsS https://images.openimages.cloud/index.json \
  | jq -r '.images[] | select(.id=="debian-13") | .artifacts[0].glance_properties
           | to_entries[] | "--property \(.key)=\(.value)"'
```

## `versions.json` (`oic-versions/v1`)

Rebuilt from the bucket contents by the publish step of every release. Top-level keys: `schema`,
`name`, `generated_at`, `versions[]`. Each version has `version`, `built_at` and `artifacts[]`
with `variant`, `filename`, `sha256`, `sha512`, `size`, `virtual_size`, `firmware`, `arch`,
`path` and `manifest` (paths relative to `https://images.openimages.cloud/<id>/`). Use it to list,
pin or roll back versions. Images published before this file existed may not have one yet
(`versions_url` is then null in the index).

## `MANIFEST.json`

Written by the reusable build workflow next to the artifact; `MANIFEST-<variant>.json` when a
version has several variants.

| Field | Meaning |
|---|---|
| `name` | Image id (repository slug) |
| `version`, `variant`, `format`, `filename` | What was built |
| `sha256` | Digest of the qcow2, the value covered by the cosign signature |
| `upstream_url` | Upstream artifact the image was built from, when applicable |
| `built_at` | Build time, ISO 8601 UTC |
| `commit`, `build_url` | Image repository commit and GitHub Actions run |
| `builder_tool`, `builder.image`, `builder.digest` | Build engine and builder container |
| `signed`, `bundle` | Signature status and bundle file name |
| `sha512`, `size`, `virtual_size`, `firmware`, `arch` | Added at publication for importers; absent from manifests published before November 2026 |

## osism openstack-image-manager export

[`/osism/images.yml`](https://images.openimages.cloud/osism/images.yml) describes the catalog in
the format of [osism/openstack-image-manager](https://github.com/osism/openstack-image-manager):

```sh
curl -fsSo oic-images.yml https://images.openimages.cloud/osism/images.yml
openstack-image-manager --cloud admin --images oic-images.yml --latest
```

- One entry per artifact, with `multi: true`: the newest version keeps the stable name, older ones
  are renamed `<name> (<version>)` by the image manager.
- Checksums are the sha256 of the signed manifest. The image manager does **not** verify cosign
  signatures; use [oic-sync](oic-sync.md) or verify by hand if you need that.
- Left out: the service images (`octavia-amphora`, `manila-service-image`,
  `trove-guest-image`) and images whose `os_distro` is not accepted by the osism schema (Amazon
  Linux, Alpaquita). The file header lists the current exclusions.

## Download statistics

`/_stats.json` is computed by the `images-router` Worker from Workers Analytics Engine: `window`
is `rolling-90d` (or `all-time` when long-term totals are enabled), with totals per image,
version and file. Downloads made by the project's own CI are excluded by User-Agent.
